
# Задание 3. Открытие депозитов онлайн

### ADR: Архитектура MVP для открытия депозитов

### <a name="_b7urdng99y53"></a>**Название задачи:** Архитектура MVP для цифровизации открытия депозитов
### <a name="_3bfxc9a45514"></a>**Функциональные требования**

| **№** | **Действующие лица/системы** | **Use Case**             | **Описание**                                                                                                                                                        |
|:-----:|:-----------------------------|:-------------------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|   1   | Клиент, Сайт                 | Подача заявки на депозит | 1. Клиент выбирает депозит на сайте<br>2. Вводит ФИО и телефон<br>3. Система шифрует данные<br>4. Заявка передается в CRM кол-центра                                |
|   2   | Клиент, Интернет-банк        | Открытие депозита онлайн | 1. Авторизованный клиент выбирает депозит<br>2. Видит персонализированную ставку<br>3. Указывает счёт/сумму<br>4. Подтверждает SMS<br>5. Заявка создается в очереди |
|   3   | Оператор кол-центра          | Обработка заявки с сайта | 1. Получает уведомление о новой заявке<br>2. Звонит клиенту<br>3. Фиксирует решение в CRM                                                                           |
|   4   | Сотрудник бэк-офиса          | Обработка заявки из ИБ   | 1. Получает заявку в АБС<br>2. Проверяет данные<br>3. Рассчитывает ставку (при необходимости)<br>4. Подтверждает открытие                                           |
|   5   | АБС                          | Управление ставками      | 1. Хранение актуальных ставок<br>2. Расчет персонализированных ставок<br>3. Механизм согласования спец. условий                                                     |
|   6   | Система                      | Отправка уведомлений     | 1. SMS при подтверждении заявки<br>2. SMS при открытии депозита                                                                                                     |

### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

| **№** | **Требование**                    |
|:-----:|:----------------------------------|
|   1   | Шифрование трафика (TLS 1.3+)     |
|   2   | Время отклика UI <500 мс          |
|   3   | Доступность 99.9% для ИБ и сайта  |
|   4   | Изоляция нагрузки на АБС          |
|   5   | Совместимость с .NET 4.5 и Java 8 |
|   6   | Автоматический failover между ЦОД |
|   7   | Ролевая модель доступа к ставкам  |

**Обоснование решений:**
1. **Микросервис депозитов** - устраняет зависимость от Excel, сохраняя security-ограничения
2. **Кэш микросервиса депозитов** - обеспечивает производительность <500 мс для UI
3. **Асинхронная обработка** - Kafka гарантирует доставку при перегрузках
4. **Шифрование** - TLS 1.3 на всех внешних интерфейсах

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

**Альтернатива: Прямая интеграция ИБ-АБС**
* *Преимущества:* Проще реализация
* *Недостатки:* Нарушает R1 FURPS+, риск перегрузки АБС

**Недостатки выбранного решения:**
1. Технический долг (.NET 4.5) ограничивает выбор технологий
2. Вертикальное масштабирование АБС - потенциальное узкое место
3. Ручная обработка в MVP сохраняет операционные издержки

**Риски:**
1. Задержки из-за сложности интеграции с legacy АБС
2. Недостаточная производительность Oracle при росте нагрузки
3. Сопротивление сотрудников бэк-офиса новым процессам

**Уменьшение рисков:**
1. Введение read-only реплик Oracle для запросов
2. Обучение сотрудников до запуска MVP
