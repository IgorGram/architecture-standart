
### <a name="_b7urdng99y53"></a>**Название задачи:** Асинхронная выгрузка ставок через Kafka

### <a name="_3bfxc9a45514"></a>**Функциональные требования**

| **№** | **Действующие лица/системы**   | **Use Case**       | **Описание**                                                                                               |
|:-----:|:-------------------------------|:-------------------|:-----------------------------------------------------------------------------------------------------------|
|   1   | Микросервис депозитов          | Публикация событий | 1. Обнаружение изменения ставок<br>2. Отправка события в Kafka                                             |
|   2   | Микросервис выгрузки депозитов | Обработка событий  | 1. Подписка на топик Kafka<br>2. Запрос актуальных ставок<br>3. Генерация CSV-файла<br>4. Загрузка на SFTP |
|   3   | CRM кол-центра                 | Загрузка ставок    | 1. Получение информации об изменении файла ставок<br>2. Загрузка обновлённого файла со ставками            |

### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

| **№** | **Требование**                            |
|:-----:|:------------------------------------------|
|  1    | Гарантированная доставка событий          |
|   2   | Автоматическое восстановление после сбоев |
|   3   | Мониторинг очереди событий                |

### <a name="_qmphm5d6rvi3"></a>**Решение**

Для решения проблемы передачи данных в чужой контур необходимо:

* Развернуть `SFTP` сервер, который будет доступен их обоих контуров;
* Доработать микросервис депозитов, что бы он посылал сообщение на каждое изменение депозитных ставок;
* Разработать дополнительный микросервис, который будет подписываться на топик kafka, в который будут 
  приходить события об изменении ставок депозитов. По этому событию он должен сделать запрос в микросервис
  депозитов, что бы получить актуальные ставки, после чего сформировать CSV файл на основе этих данных, 
  запаковать его для уменьшения трафика и загрузить на `SFTP` сервер. Путь до этого файла должен быть  
  фиксированный, например `/deposits.tar.gz`.
* Доработать силами партнёров их CRM, что бы она периодически запрашивала с помощью `SFTP` команды `ls -l`, 
  не изменился ли файл со ставками депозитов, и если изменился - то скачивал бы его, распаковывала, и 
  обновляла у себя информацию о ставках.

**Обоснование решений:**
1. **Разделение ответственности**:
    - Микросервис депозитов: управление ставками и событиями
    - Микросервис выгрузки депозитов: обработка событий и файловые операции
2. **Надёжность**:
    - Kafka гарантирует доставку событий
    - Механизм повторов для SFTP-операций
3. **Масштабируемость**:
    - Возможность запуска нескольких экземпляров микросервиса выгрузки депозитов
    - Балансировка нагрузки через потребителей Kafka
4. **Производительность**:
    - Асинхронная обработка не блокирует основной сервис
    - Параллельная обработка событий

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

**Альтернатива: Прямая интеграция**
* *Преимущества:* Проще архитектура
* *Недостатки:* Риск влияния на основной сервис, нет гарантий доставки

**Недостатки выбранного решения:**
1. Дополнительная сложность в поддержке
2. Задержка в обновлении файлов
3. Требует дополнительных ресурсов
